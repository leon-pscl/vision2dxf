# Coding-Agent Instructions — Design 3

## Anthropometric Surface Reconstruction and Constrained Mesh Flattening

## Mission

Instrument and evaluate the existing **Design 3: Anthropometric Surface Reconstruction and Constrained Mesh Flattening** program. Produce defensible values for the five Chapter 3 trade-off metrics:

1. **Python-tracked peak memory consumption (MB)** — minimize.
2. **Required-feature completeness rate (%)** — maximize.
3. **Median pattern-generation time (s)** — minimize.
4. **Pattern-dimension mean absolute error (cm)** — minimize.
5. **Radon Maintainability Index (0–100)** — maximize.

All primary values must be generated by the Design 3 program and frozen project references. Do not estimate values, copy results from publications, remove difficult cases, or tune the algorithm after viewing final-case results.

---

# Design Definition

Design 3 shall:

1. Read the same camera-derived, tailor-confirmed measurement YAML used by Designs 1 and 2.
2. Construct a simplified three-dimensional anthropometric garment-support surface.
3. Apply garment ease before or during surface construction using a frozen rule.
4. Place approved seam, fold, waist, armscye, sleeve, and dart paths.
5. Split the surface into disk-topology panel regions.
6. Triangulate the regions with consistent orientation.
7. Flatten every three-dimensional panel mesh into two dimensions using one declared constrained parameterization method.
8. Convert flattened boundaries into the common Pattern JSON-compatible representation.
9. Add seam allowances, grainlines, notches, labels, folds, darts where applicable, and stitch-pair identifiers.
10. Validate and export through the same common DXF module used by Designs 1 and 2.

The reconstructed mesh is an **anthropometric surrogate surface**, not a complete body scan. State this limitation in the implementation documentation.

## Prohibited Fallbacks

Design 3 must not:

- Load or transform the GarmageSet-derived Design 2 base block.
- Retrieve a pre-drafted pattern template.
- Compute final 2D panels with Design 1 drafting equations.
- Replace failed flattening with hand-edited coordinates.
- Change mesh resolution, seam locations, weights, pins, solver, tolerances, or iteration limits after final benchmarking begins.
- Treat invalid or out-of-domain output as successful.

Unsupported cases must return a structured failure such as `MISSING_MEASUREMENT`, `INVALID_SECTION_ORDER`, `MESH_INVALID`, `NONDISK_PANEL`, `SOLVER_DID_NOT_CONVERGE`, `FLIPPED_TRIANGLES`, `SEAM_MISMATCH`, `BOUNDARY_INVALID`, or `OUT_OF_DOMAIN`.

# Required Algorithm

## Stage A — Input Validation

1. Parse the adapted GarmentCode-style YAML.
2. Read only `confirmed_value`.
3. Convert all values to millimetres.
4. Reject missing, non-finite, non-positive, or unsupported values.
5. Verify anatomical-section order and required vertical spacing.
6. Verify that girths and width/depth data can produce valid cross-sections.
7. Record any derived value and the rule that produced it.

## Stage B — Cross-Section Construction

At each approved anatomical or garment station, construct an ordered ring. If the section is elliptical:

```text
x(theta) = a * cos(theta)
y(theta) = b * sin(theta)
z(theta) = section_height
```

Choose \(a\) and \(b\) so the section matches the confirmed girth within the frozen numerical tolerance and respects the available width/depth ratio. If a superellipse is used, document its exponent and circumference-solving method.

Apply garment ease through a frozen rule before surface meshing. Do not add equal radial ease unless that is the approved configuration; bust, waist, hip, back, and front distributions may differ but must be fixed before final testing.

## Stage C — Surface Construction

1. Generate rings with the same ordered angular samples or another fixed correspondence.
2. Align anatomical landmarks between adjacent rings.
3. Connect adjacent rings using the frozen topology.
4. Construct sleeves separately if included.
5. Orient triangle faces consistently.
6. Verify no duplicate vertices, zero-area triangles, non-finite coordinates, unintended disconnected components, or nonmanifold internal edges.

## Stage D — Panel Segmentation

1. Place approved seam and construction paths on mesh edges or as constrained cut polylines.
2. Split the garment surface into named panel regions.
3. Assign matching stitch IDs to paired boundaries.
4. Verify that each region is connected and has disk topology before flattening.
5. Reject an unflattenable topology rather than introducing an unapproved cut.

## Stage E — Triangulation

Use one deterministic triangulation method. Preserve seam vertices and constrained boundaries. Record vertex and face counts by panel. Do not use adaptive refinement during final trials unless its rule and limits were frozen beforehand.

## Stage F — Initial Parameterization

Create a valid initial 2D map using the declared method, such as harmonic or least-squares conformal mapping. Pin the minimum number of vertices needed to remove rigid motion, selected through a deterministic rule. Verify finite 2D coordinates and initial orientation.

## Stage G — Constrained Flattening

Minimize the declared flattening objective. A conceptual objective may be:

```text
E_total =
    w_distortion * E_distortion
  + w_seam       * E_seam
  + w_symmetry   * E_symmetry
  + w_grain      * E_grain
  + w_boundary   * E_boundary
```

The implementation must document the actual equations and solver. At minimum:

- `E_distortion` limits edge, angle, area, or ARAP deformation.
- `E_seam` reduces length differences between paired seams.
- `E_symmetry` controls intended mirrored panel relationships.
- `E_grain` aligns the declared grain direction.
- `E_boundary` controls smoothness or approved straight segments.

Use fixed weights, tolerances, and maximum iterations. Record convergence status and iteration count.

## Stage H — Flattening Validation

Calculate these diagnostics for every panel:

- Flipped-triangle count and percentage.
- Mean and maximum edge-length distortion.
- Mean and maximum triangle-area distortion.
- Optional angular distortion when supported.
- Paired-seam absolute and relative mismatch.
- Boundary self-intersection count.
- Connected-component count.
- Solver convergence and final objective.

Reject the output if it violates a frozen mandatory tolerance.

## Stage I — Pattern Conversion

1. Extract the ordered outer boundary and approved internal curves from each flattened panel.
2. Fit lines, arcs, or Bézier curves within the frozen maximum-deviation tolerance.
3. Recheck boundary closure and self-intersection after fitting.
4. Generate seam and cutting lines.
5. Add allowances, grainlines, notches, labels, folds, darts, and stitch-pair identifiers.
6. Convert to the common Pattern JSON-compatible object.
7. Run the common validator.
8. Export with the common DXF exporter.

# Metric 1 — Peak Memory Consumption

## Definition

Measure the initialized reconstruction and flattening configuration retained in Python plus one complete reconstruction, meshing, flattening, validation, pattern conversion, and DXF export.

```text
peak_memory_mb = peak_bytes / (1024 ** 2)
```

## Procedure

Run every trial in a fresh child process. Import common libraries before tracing. Then:

```python
import gc
import tracemalloc

gc.collect()
tracemalloc.start()
engine = build_design_3_engine(
    reconstruction_config="design_3/config/reconstruction.yaml",
    topology_config="design_3/config/topology.yaml",
    flattening_config="design_3/config/flattening.yaml",
)
tracemalloc.reset_peak()
pattern = engine.generate_pattern(measurements, garment)
validated = validate_common_pattern(pattern)
dxf_path = export_common_dxf(pattern, temporary_output)
current_bytes, peak_bytes = tracemalloc.get_traced_memory()
tracemalloc.stop()
peak_memory_mb = peak_bytes / (1024 ** 2)
```

Starting tracing before engine construction includes retained Python allocations of the Design 3 configuration. Resetting the peak after construction removes temporary initialization spikes but retains current initialized allocations. This matches the required policy for Designs 1 and 2.

Because SciPy, NumPy, libigl, or other compiled libraries may allocate outside Python's traced allocator, label the result **Python-tracked peak memory**. Optionally record process RSS as a diagnostic, but do not replace the official metric unless the Chapter 3 protocol is revised for all alternatives before results are viewed.

## Repetitions

- Five untimed warm-ups per case in fresh child processes.
- At least 30 measured memory trials per case.
- Preserve every trial and failure.
- Report case medians and interquartile ranges.
- Use the median across mandatory measured trials as the Chapter 3 value.

# Metric 2 — Required-Feature Completeness

For case \(j\):

```text
completeness_j = 100 * complete_applicable_features / applicable_features
```

A feature counts as complete only when it is present, correctly referenced, correctly positioned according to its rule, and geometrically valid. A flattened outline without production annotations is not a complete pattern.

Write one row per item:

```text
case_id,feature_id,applicable,present,valid,complete,failure_reason
```

Calculate:

- **Macro completeness:** arithmetic mean of case percentages.
- **Micro completeness:** total complete items divided by total applicable items.

Use macro completeness as the Chapter 3 value. Retain the micro value as supporting information.

# Metric 3 — Pattern-Generation Time

## Timed Boundary

Initialize the engine and load static configurations before timing. The timed recurring operation must include:

- Input validation and unit conversion.
- Cross-section and ease computation.
- Three-dimensional surface construction.
- Seam placement and segmentation.
- Triangulation.
- Initial parameterization.
- Constrained flattening.
- Mesh and flattening diagnostics required for acceptance.
- Two-dimensional boundary extraction and fitting.
- Production-feature generation.
- Common validation.
- Pattern serialization.
- DXF creation.

Exclude:

- Python imports.
- Engine/configuration initialization.
- Fixture-file loading.
- Camera capture and image processing.
- Tailor review.
- Interface rendering.
- A0 nesting.

## Procedure

Run time measurement in a separate pass with `tracemalloc` disabled:

```python
from time import perf_counter_ns

engine = build_design_3_engine(reconstruction_cfg, topology_cfg, flattening_cfg)
start_ns = perf_counter_ns()
pattern = engine.generate_pattern(measurements, garment)
validated = validate_common_pattern(pattern)
dxf_path = export_common_dxf(pattern, temporary_output)
end_ns = perf_counter_ns()
time_s = (end_ns - start_ns) / 1_000_000_000
```

Complete five warm-ups and at least 30 measured time trials per case. Use the overall median as the Chapter 3 value. Also report case medians, interquartile ranges, mesh sizes, and solver iterations to explain performance variation.
